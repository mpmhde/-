..Сортировка выбором (Selection Sort) — на каждом шаге алгоритма находят минимальный
элемент среди последних и меняют его местами с текущим элементом в массиве.
Пример: Для последовательности [8, 3, 6, 1, 5], сначала найдем минимальный элемент (1), поместим его первым, затем снова найдем минимум среди оставшихся элементов и так далее.
Итоговая последовательность: [1, 3, 5, 6, 8].
Временная сложность:
Худший случай: O(n²)
Лучший случай: O(n²)
Средний случай: O(n²)

Объяснение:
Алгоритм состоит из двух вложенных циклов.

Внешний цикл выполняется n раз (для каждого элемента массива).

Внутренний цикл на каждой итерации внешнего цикла ищет минимальный элемент в неотсортированной части массива. На первой итерации он просматривает n элементов, на второй — n-1, и так далее.
Количество сравнений можно выразить суммой: n + (n-1) + (n-2) + ... + 1 = n(n-1)/2.
Эта сумма пропорциональна n², независимо от исходной упорядоченности массива. Даже если массив уже отсортирован, алгоритм все равно выполнит все сравнения.


..Сортировка обменом (пузырьком) (Bubble Sort) — алгоритм проходит по списку несколько
раз, сравнивая соседние элементы и меняя их местами, если они находятся в неправильном
порядке. Процесс повторяется до тех пор, пока список полностью не отсортируется.
Временная сложность:

Худший случай: O(n²) (массив отсортирован в обратном порядке)

Лучший случай: O(n) (массив уже отсортирован)

Средний случай: O(n²)

Объяснение:

Худший случай: Алгоритм требует многократных проходов по массиву. В худшем случае (массив отсортирован в обратном порядке) потребуется n-1 проход, и на каждом проходе будет выполнено n-1 сравнений и обменов. Суммарное количество операций пропорционально n².

Лучший случай: Если массив уже отсортирован, улучшенная версия алгоритма (с флагом swapped) совершит всего один проход по массиву, выполнив n-1 сравнений и ни одного обмена. Это дает линейную сложность O(n).


Пример: У нас имеется массив [5, 2, 9, 1, 5]. После первого прохода список становится таким: [2, 5, 1, 5, 9] (число 9 переместилось на последнее место).
Процесс повторяется до полной сортировки: [1, 2, 5, 5, 9]


..Сортировка вставками (Insertion Sort) — алгоритм строит отсортированную часть списка,
постепенно вставляя каждый элемент на своё место. Он начинает с первого элемента и
перемещается вправо, сравнивая каждый элемент с предыдущими элементами и вставляя его
на правильное место.
Временная сложность:

Худший случай: O(n²) (массив отсортирован в обратном порядке)

Лучший случай: O(n) (массив уже отсортирован)

Средний случай: O(n²)

Объяснение:

Худший случай: Каждый новый элемент приходится вставлять в самое начало отсортированной части. Для вставки k-го элемента в худшем случае требуется k сравнений и обменов. Суммарно: 1 + 2 + 3 + ... + (n-1) = n(n-1)/2 ~ O(n²).

Лучший случай: Если массив отсортирован, то на каждом шаге новый элемент будет сразу занимать правильную позицию (в конце отсортированной части), и для его вставки потребуется всего одно сравнение. Алгоритм выполнит n-1 сравнение, что дает O(n).
Пример: Имеем последовательность [3, 1, 4, 2]. Первый элемент (3) оставляем на месте, второй (1) ставим перед ним, третий (4) размещаем после 3, четвертый (2) переставляем после 1:
итоговый порядок — [1, 2, 3, 4].


..Сортировка слиянием (Merge Sort) — алгоритм состоит в разделении массива пополам,
сортировке половин и их слиянии.
Временная сложность:

Худший случай: O(n log n)

Лучший случай: O(n log n)

Средний случай: O(n log n)

Объяснение:
Это алгоритм "разделяй и властвуй".

Фаза разделения: Массив рекурсивно делится пополам. Глубина рекурсии (количество уровней деления) составляет log₂ n (по основанию 2).

Фаза слияния: На каждом уровне рекурсии выполняется операция слияния всех подмассивов этого уровня. Суммарно на каждом уровне мы обрабатываем все n элементов.

Поскольку у нас log n уровней, и на каждом уровне выполняется работа O(n), общая сложность составляет O(n log n). Эта сложность гарантирована и не зависит от исходных данных.
Пример: Берём массив [7, 2, 5, 3]. Разделяем на два подмножества: [7, 2] и [5, 3]. 
Сортируем каждую половину отдельно, потом сливаем обратно: итог — [2, 3, 5, 7].


..Сортировка Шелла (Shellsort) — является модификацией сортировки вставками, сортирует
между собой элементы, стоящие на местах, кратных определённому шагу.
Временная сложность:

Зависит от выбора последовательности шагов.

В худшем случае: O(n²) для простых последовательностей, O(n log² n) для последовательности Кнута, O(n log n) для лучших последовательностей.

Объяснение:
Сложность анализа этого алгоритма нетривиальна, так как она сильно зависит от используемой последовательности шагов (gap). Идея в том, что на начальных этапах (с большим шагом) алгоритм делает массив "более упорядоченным", что позволяет на последующих этапах (с малым шагом) сортировке вставками работать очень быстро. Эмпирически сложность часто лежит между O(n log n) и O(n¹․⁵). Гарантированной оценки O(n log n), как у слиянием или быстрой, у нее нет.
Пример: Исходный массив [23, 12, 1, 8, 34, 17]. Применяя шаг (h = 3), мы получаем частично отсортированный массив, затем уменьшаем шаг и окончательно сортируем массив: [1, 8, 12, 17, 23, 34].


..Быстрая сортировка (Quick Sort) — один из самых известных и широко используемых
алгоритмов сортировки. Алгоритм состоит в выборе опорного элемента, разделении массива
на две части относительно опорного (одна — все элементы, меньшие опорного элемента,
вторая — большие), и в сортировке полученных частей рекурсивным вызовом себя от них.
Временная сложность:

Худший случай: O(n²)

Лучший случай: O(n log n)

Средний случай: O(n log n)

Объяснение:
Это также алгоритм "разделяй и властвуй".

Лучший/Средний случай: В среднем опорный элемент делит массив на две примерно равные части. Глубина рекурсии составит O(log n), а на каждом уровне выполняется работа по разделению (проход по текущему подмассиву), суммарно O(n) на уровень. Итог: O(n log n).

Худший случай: Возникает, когда опорный элемент постоянно оказывается наименьшим или наибольшим (например, если брать крайний элемент из уже отсортированного массива). В этом случае массив делится на части размером 0 и n-1. Глубина рекурсии становится n, а общее количество операций — n + (n-1) + ... + 1 ~ O(n²).
Пример: Начнём с массива [10, 5, 3, 8, 2, 6, 4, 7]. Выбираем первый элемент (10) как pivot, перебрасываем числа меньше него влево, большие — вправо.
Результат первой итерации: [5, 3, 8, 2, 6, 4, 7, 10]. Далее продолжаем рекурсию над каждой стороной.


..Пирамидальная сортировка — алгоритм строит кучу из исходного списка, затем постепенно
извлекает наибольший элемент из кучи и помещает его в конец списка.
Временная сложность:

Худший случай: O(n log n)

Лучший случай: O(n log n)

Средний случай: O(n log n)

Объяснение:
Алгоритм состоит из двух этапов:

Построение кучи (Heapify): Имеет сложность O(n).

Извлечение элементов: Выполняется n раз. Каждая операция извлечения максимального элемента (замена корня с последним элементом и просеивание вниз) в худшем случае занимает O(log n) времени, так как высота кучи равна log n.

Таким образом, общая сложность определяется вторым этапом: n * O(log n) = O(n log n). Эта сложность является гарантированной.

Пример: Дано массив [4, 10, 3, 5, 1]. Строится max-куча: [10, 5, 3, 4, 1]. Извлекаем корень (10), восстанавливаем кучу и снова извлекаем максимум.
Последовательно собираем отсортированный массив: [1, 3, 4, 5, 10].


..Последовательный (линейный) поиск — простейший вид поиска заданного элемента на
некотором множестве. Осуществляется путём последовательного сравнения очередного
рассматриваемого значения с искомым до тех пор, пока эти значения не совпадут. Этот метод
является наименее эффективным, так как его временная сложность составляет O(n), где n —
количество элементов в списке. Однако он прост в реализации и может быть полезен для
небольших списков или в тех случаях, когда данные не отсортированы.
Временная сложность:

Худший случай: O(n) (элемента нет или он последний)

Лучший случай: O(1) (элемент первый)

Средний случай: O(n) (элемент в середине массива)

Объяснение:
В худшем и среднем случае алгоритму, возможно, придется проверить все n элементов или около того. Количество операций растет линейно с ростом размера массива. В лучшем случае он находит элемент сразу.
Пример: Ищем число 6 в списке [3, 7, 2, 6, 8, 1]. Проверяем последовательно элементы, находим нужный на четвертой позиции.


..Бинарный (двоичный, дихотомический) поиск — это поиск заданного элемента на
упорядоченном множестве, осуществляемый путём неоднократного деления этого множества
на две части таким образом, что искомый элемент попадает в одну из этих частей. Поиск
заканчивается при совпадении искомого элемента с элементом, который является границей
между частями множества или при отсутствии искомого элемента. Преимуществом бинарного
поиска является более низкая трудоёмкость по сравнению с последовательным поиском.
Недостаток заключается в том, что он применим только на отсортированных множествах.
Временная сложность:

Худший случай: O(log n)

Лучший случай: O(1)

Средний случай: O(log n)

Объяснение:
На каждом шаге алгоритм уменьшает область поиска вдвое. Вопрос: "Сколько раз нужно поделить n на 2, чтобы получить 1?".
Это k = log₂ n. Именно столько шагов в худшем случае потребуется алгоритму. Рост логарифмической функции очень медленный, что делает алгоритм чрезвычайно эффективным для больших отсортированных массивов.
Пример: Найти число 11 в отсортированном массиве [1, 3, 5, 7, 9, 11, 13, 15]. Начинаем с середины (7), сравниваем и двигаемся в правую половину. 
Затем рассматриваем среднюю позицию правой половины (11), совпадающую с искомым значением.


..Интерполирующий поиск — это алгоритм поиска для отсортированных наборов данных,
таких как массивы или списки. Он предсказывает позицию нужного элемента на основе
разницы значений. Эффективен, если элементы распределены достаточно равномерно.
Временная сложность:

Худший случай: O(n) (данные сильно неравномерно распределены)

Лучший случай: O(1)

Средний случай: O(log log n)

Объяснение:
Этот алгоритм не просто делит область поиска пополам, а пытается предугадать позицию искомого элемента на основе его значения и значений на границах (по принципу поиска в телефонной книге).

Средний случай: При равномерном распределении данных на каждом шаге область поиска сокращается не в 2 раза, а значительно сильнее. Количество шагов, необходимых для нахождения элемента, пропорционально логарифму от логарифма от n, что для очень больших массивов (например, из миллиарда элементов) означает всего около 5-6 шагов против ~30 у бинарного поиска.

Худший случай: Если данные распределены очень неравномерно (например, экспоненциально), алгоритм вырождается в линейный поиск.
Пример: Есть отсортированный массив чисел [1, 3, 5, 7, 9, 11, 13, 15]. Мы ищем число 11. Интерполяционная формула позволит сразу приблизиться ближе к нужной позиции, сократив количество шагов.


..Поиск по Фибоначчи — это эффективный алгоритм поиска, используемый для нахождения
целевого значения в отсортированной коллекции, такой как массив или список. По принципу
он аналогичен бинарному поиску, но использует числа Фибоначчи для определения позиций
для сравнения.
Временная сложность:

Худший случай: O(log n)

Лучший случай: O(1)

Объяснение:
Этот алгоритм похож на бинарный поиск, но вместо деления пополам он делит массив в пропорции золотого сечения, используя числа Фибоначчи. Хотя он выполняет в среднем на ~4% больше сравнений, чем бинарный поиск, он может быть выгоднее на системах, где деление — дорогая операция (так как он использует только сложение и вычитание). Асимптотически его сложность также равна O(log n), но константа скрытая behind the O-notation будет немного другой. Утверждение про O(log φ n) верно, но так как φ является константой, по свойствам логарифмов O(log φ n) = O(log n / log φ) = O(log n).

Пример: Пусть дан отсортированный массив [1, 3, 5, 7, 9, 11, 13, 15]. Нужно найти число 11.
Используя длины сегментов по числам Фибоначчи, выбираем начальные точки для проверки и переходим по сегментам, исключая ненужные области.
